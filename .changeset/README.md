# Changesets

Hello and welcome! This folder has been automatically generated by `@changesets/cli`, a build tool that works
with multi-package repos, or single-package repos to help you version and publish your code. You can
find the full documentation for it [in our repository](https://github.com/changesets/changesets).

We have a quick list of common questions to get you started engaging with this project in
[our documentation](https://github.com/changesets/changesets/blob/main/docs/common-questions.md).

## This repo (CC-25)

`co-canvas` (`apps/cli`) is the sole versioned package — one product, one version. Its version drives
the npm publish, the GitHub Release tag, and the standalone `co-canvas-hub` binary names. Every other
workspace package is private and internal, bundled into `co-canvas` rather than released on its own,
so `pnpm changeset` only ever bumps `co-canvas`.

CI has a `changeset` gate: any pull request that changes the `co-canvas` package must include a
changeset, so no user-facing change silently drops out of the changelog or version bump. Add one with
`pnpm changeset` (pick the bump level + summary).

If a change touches the package but genuinely needs no release (comment/test-only, chore), commit an
empty changeset instead — `pnpm changeset add --empty` — which satisfies the gate without producing a
version bump. The empty changeset must be committed; the gate diffs committed history against `main`.
